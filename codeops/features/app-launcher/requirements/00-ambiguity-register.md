## Resolution Notes

**AR-1 / AR-2 / AR-3 / AR-4:** The port directives from the planning session. The
byte-identical rule means: props, types, defaults, behavior, styles, DOM output, aria attributes
and test assertions are frozen; only formatting (Prettier), the 3 comment references (AR #8), the
scope adaptation and sample-copy de-branding (AR #9) may differ. Any defect found while porting
becomes a recorded finding, never a fix in this feature.

**AR-5:** The workbench is `apps/web/src/dev/app-launcher-workbench.tsx` (5 samples: M365 flow,
full docking stress, trigger-anchored list, drawer toolbar, German localization) with
`apps/web/src/dev/app-launcher-logos.tsx` (6 hand-drawn sample logos). Per-component variant
stories for the six blocks beyond the composed samples are new story content under the repo's
definition of done; they prove the frozen behavior, they do not extend it.

**AR-6:** Two RDs mirror the proven two-layer split of the existing features (shell vs. blocks);
each RD is independently useful and independently testable. The composed `AppLauncher` story is
complete only when both RDs are implemented; the shell itself works with any caller content.

**AR-7:** Ported test inventory: `app-launcher.spec`, `app-launcher-trigger.spec`,
`app-launcher-search.spec`, `app-launcher-section.spec`, `app-launcher-grid.spec`,
`app-launcher-list.spec`, `app-launcher-item.spec`, `app-launcher-item.impl` (8 files, 37 tests
including the source package-exports test which merges into AR #12's pin). The source
`test/setup.ts` is not ported — the destination's setup already registers jest-dom and cleanup.

**AR-8:** The closed edit list: (1) `AppLauncher.tsx` JSDoc — drop the stale "and (in later
iterations) the panel behavior" phrase; (2)-(3) `app-launcher.spec.test.tsx` — reword the two
"inspected ... in the workbench" comments to the Storybook equivalent. No other comment or code
edits beyond formatting.

**AR-9:** Neutral sample copy: "Virtuo Resource Planning" → "Resource Planning" (workbench doc
comment and sample data), the "VirtuoApp" brand text in the drawer sample dropped. All other
sample data, labels and German strings stay as ported.

**AR-10:** The `AppLauncher` story carries all five samples; the other six story files hold
component-level variants. Size check performed at planning: the composed story stays under the
repository's ~700-line split threshold without shared fixtures, so no `tsconfig.build.json` or
story-convention change is needed.

**AR-14:** Verified during planning: `resolvePositioningShorthand` (exported by
`@fluentui/react-components`, checked in `dist/index.d.ts`) and `GridDots20Regular`
(`@fluentui/react-icons`) both exist in the installed versions; no manifest change is required.

**AR-19:** No `docs/` set exists and none is created; the package README remains the documented
surface for the ported family.

**All items resolved.** No deferrals. No complexity escalations — the feature adds components to
the existing package using existing dependencies, patterns and test infrastructure.
