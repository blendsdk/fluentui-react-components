## Resolution Notes

**AR-01:** The tab strip is a separate navigation concern. The fui9 tab system is a drawer, not
bar navigation, and is unused; it is excluded so the bar shell and M365 command states stay small.

**AR-05:** The bar carries no horizontal or vertical padding. The launcher button and trailing
48px icon commands sit flush with the window edges. `AppBarTitle` carries the 8px inline margin.
The bar uses `min-height` rather than a fixed height so text zoom can grow it; at normal text it is
exactly 48px.

**AR-06:** `headingLevel` and `href` are mutually exclusive at the type level. The default root is
`<span>`; `headingLevel` renders `<h1>`–`<h6>`; `href` renders `<a>`. The title never forces an
`h1`, avoiding the fui9 heading-hierarchy defect.

**AR-07:** The forced visual props keep every bar command consistent. The accessible-name union
makes an icon-only button impossible to write without a name. `disabled` and `disabledFocusable`
pass through to Fluent `Button`.

**AR-13:** The white overlays come from the reviewed workaround in
`packages/react-components/src/components/AppLauncher/stories/AppLauncherStoryApps.story.tsx:245-260`.
No Fluent token represents a translucent white overlay on a brand surface.

**AR-17:** The geometry follows the fui9 48px bar and the M365 waffle. The open-state highlight is
CSS-only because Fluent's `PopoverTrigger` injects `aria-expanded` into a custom trigger. The
stories use the Fluent `GridDots20Regular` waffle, matching M365.

**AR-18:** The visual gate is real: `pnpm verify` and `pnpm storybook:build` prove the code
compiles and the stories render, but only the user can approve the 48px geometry, paddings,
hover/pressed colors and disabled states.
