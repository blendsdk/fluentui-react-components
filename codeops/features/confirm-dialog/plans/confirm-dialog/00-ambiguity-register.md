**AR-5 (delegated):**

```text
Authority: AI — delegated by --auto-design
Eligibility: internal/public interface mechanism within the user-approved typed-outcome contract
  (requirements AR #8/#20); compile-time only; no behavior, scope or acceptance change; reversible
  pre-1.0.
Objective: literal-typed outcomes at the call site with inline callbacks — the RD-01 AC 7
  inference promise — while keeping one documented generic-preserving assertion (AR-20).
Decision: the forwarded component is asserted to an object type with two call signatures
  (pair first, actions generic second), preceded by displayName assignment.
Evidence: compile experiment this session — a single union-signature assertion makes inline
  `onResolve` parameters implicitly `any` (contextual typing fails across the union of the two
  callback shapes), while the two-overload object assertion compiles both witnesses and keeps
  `'cancel' | 'discard' | 'save'` inference; `React.forwardRef` accepts the generic inner
  function.
Rejected alternatives: single union-signature assertion (breaks inline-callback inference —
  verified); declaring the callback as `(value: V | boolean) => void` on both variants (weakens
  the pair/actions discriminated contract).
Strongest counterargument: an overload object may read as two components to newcomers —
  mitigated by the JSDoc on `ConfirmDialogProps` and the inline examples.
Confidence: High — would change if React/TypeScript ship a cast-free generic forwardRef that
  preserves contextual inference.
Hardening: not required — compile-time only, empirically verified; zero runtime effect.
Policy version: 1 · Root invocation ID: MP-CONFIRM-DIALOG-2026-10-16
Reopen triggers: a cast-free generic forwardRef pattern becomes idiomatic; the inference pins
  fail under a TypeScript upgrade.
```

**AR-7 / AR-8 / AR-9 (delegated):** The mechanisms are pinned in `03-01 §Focus and accessibility
machinery` and `03-02 §Provider mechanics`. Key evidence: `useFocusFirstElement.js` (installed
`@fluentui/react-dialog@9.18.5`) runs its focus move in `React.useEffect`, so layout effects and
passive effects of the component run before it; the browser's disable-time focus fixup to
`<body>` and jsdom's retained focus are both covered by the busy guard; the error-dialog spec
documents jsdom's synchronous surface removal on close (`error-dialog.spec.test.tsx:465-466`),
which makes the always-rendered provider dialog testable without motion waits.
