# Testing Strategy: TileGrid RD-03

> **Parent**: [Index](00-index.md)
> **Authority**: AR-2, AR-14

## Coverage and Method

Cover every RD-03 acceptance criterion and every new AR decision with a behavioral oracle. Reuse
the existing selection/layout/SSR/type/export oracles as regressions. Apply the shared standards'
coverage targets: core behavior 90%, supporting helpers 80%, UI/glue 60%. Use the existing
`test:coverage` script and installed V8 provider to report the changed modules; no new coverage
infrastructure or CI threshold configuration is needed. Include error/cancel paths and happy paths.

Specification authors receive this document, governing specifications, requirement excerpts, and
planned interfaces, but do not read implementation logic. Expected behavior stays fixed. Newly
written cases that already pass are recorded as baseline regression coverage, not forced to fail.
Use real React/DOM interactions; jsdom measurement shims remain confined to the existing setup.
Use real pointer capture, native Tab/radio navigation, and virtualization in browser tests.

### Range Recovery Regression

ST-42 (runtime AR-20): with hidden-first anchor and current `a,b,c,d`, Shift-click `b` selects
only `b`; bring the original hidden anchor into the current list before `a`, then Shift-click `d`.
The range begins at that original anchor, producing `{hidden,a,b,c,d}`. Separately, clear the
selection/anchor, then Shift-click `b` and `d`; each absent-anchor fallback selects only its target,
so the final membership is `{d}`. Neither fallback invents a new anchor. Source: RD-01 Range
algorithm, especially its original-anchor rule. This is an additive Phase 2 oracle, authored
before the bounded correction to the inherited store.

## Test Data and Execution

Reuse `test/fixtures/tileGridFixture.ts`, existing jsdom size helpers, and current browser setup.
Small labelled fixtures belong in the test files; test wrappers may control props normally.
Do not mock React, Fluent controls, the store, geometry, or virtualizer. Fake frame scheduling is
appropriate only in controller unit tests; browser gesture tests exercise real capture/scroll.

Successful jsdom host gestures use a test-local, pointer-ID-aware capture double because the shared
fallback stubs intentionally report no capture. Record acquisition/release, restore patched methods
after each test, and assert observable active preview before success/cancel assertions. Keep a
separate forced-capture-failure case. Do not replace real browser capture or introduce a new shared
test harness (preflight PF-008).

Browser tests are the end-to-end interaction suite; no separate application/server runner is needed.
For performance, reuse the current sample counts, clock boundary, fixture, and p95 assertions;
do not alter thresholds to accommodate control/focus work. Record actual measurements.
