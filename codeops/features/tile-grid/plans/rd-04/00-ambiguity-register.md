## Resolution Notes

**AR-2:** Created `feat/tile-grid-rd-04` from `f66b816` on 2026-10-23. The RD-03 branch remains the
review boundary for its own work.

**AR-3:** Requirements AR #11 already contains the complete approval evidence: original goal, the
two direct dependencies and one browser runner, the independent **Simplify** verdict, and the direct
user approval. This plan adds no new dependency or support harness.

**AR-4:** The export pin in `packages/react-components/test/package-exports.spec.test.ts` currently
asserts that TileGrid is absent. RD-04 replaces that assertion with the complete public surface. The
package version and npm publication are not touched by this plan.

**AR-12:** User chose to treat a missing `onReorder` as disabled arranging: render no handle or
reorder actions and warn once in development. The warning is development-only and does not change
the rendered surface in production.

**AR-14:** `TileGridStrings` remains a `Partial` input on `TileGridProps` and `TileGridItemProps`;
the grid passes fully resolved strings to `renderItem`.

**AR-17:** The lookup is bounded by the mounted window, which always covers the viewport. The
collection end is reachable because the window includes the end item when the grid is scrolled to
the bottom.

**AR-19:** `@dnd-kit/core@6.3.1` attaches a document keydown listener in its pointer sensor and
cancels the drag on Escape; no custom cancel path is needed.

**AR-34:** Discovered during technical authoring. RD-04 puts `setNodeRef` on the drag handle, so the
handle is dnd-kit's active node. `DragOverlay` measures its wrapper from the active node rectangle,
which would anchor the overlay to the handle instead of the tile. The user chose a custom body
portal: the overlay captures the tile's viewport rectangle at drag start, follows `delta`, and
unmounts at drop or cancel. Separately, the root droppable hook must run inside `DndContext`; the
plan uses a small internal `TileGridRoot` component for that, with no public API change.
