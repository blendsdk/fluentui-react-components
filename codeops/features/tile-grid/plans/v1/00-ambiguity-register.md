### Resolution Notes

**AR-1:** Phase A implements the RD-02 core (geometry, four layouts, virtualization, controlled `tileSize`, anchor preservation, empty state, list semantics, pure geometry/port), the RD-01 selection store and marquee controller, and the minimal public selection wiring. RD-03 keeps focus, keyboard, selection controls, live announcements, `isSelectable`/`isDisabled`, `interactionMode`, `enableMarquee`, `onItemActivate`, `scrollResetKey`, filtering persistence, and the marquee overlay. RD-04 keeps the tile shell, actions, arranging, `@dnd-kit/core`, the full recipe, and the remaining public types.

**AR-2:** The Phase A public type is a strict subset. The final RD-02 `TileGridProps<T>`/export pin is completed by the RD-03 and RD-04 plans. The RD-02 acceptance criteria that name `TileGridItem`, `TileGridAction`, `TileGridReorderArgs`, `TileGridDragHandleProps`, `TileGridInteractionMode`, and the full export list are deferred to those plans.

**AR-3:** Click mapping is the RD-03 mapping without the rendered controls, focus model, keyboard, or announcements: plain click selects/replaces; Ctrl/Cmd toggles; Shift selects the anchor-to-target range. Clicks whose target is inside a button, link, input, select, textarea, menu item, checkbox, radio, or an element marked `data-tile-grid-interactive` do not select. `selectionMode="none"` ignores selection clicks. No public `isSelectable`/`isDisabled` in Phase A; the internal store uses `() => true`.

**AR-4:** The marquee controller is internal, not exported, and not mounted in `TileGrid`. It is a completed unit with synthetic pointer/geometry tests; RD-03 adds the overlay, pointer host, and grid-level integration. This is an explicitly accepted staged-internal-code exception; it is not public dead code.

**AR-5:** Phase A keeps `tileSize` controlled by the application. The Storybook zoom story uses a local slider; changing `tileSize` recomputes geometry and preserves the anchor. `zoomable` and `onTileSizeChange` are deferred to RD-03. The RD-02 acceptance criterion that names those props is deferred in part; controlled `tileSize` and anchor preservation remain in Phase A.

**AR-6:** The grid root is the scroll container. It uses `overflow: auto`, `height: 100%`, `min-height: 0`, and `position: relative`; the application supplies a sized parent or a native `style` height. The root's native `style` and `className` merge with the component's values. The 20K story uses a fixed-height wrapper. Window/page scroll is out of scope.

**AR-7:** Masonry uses TanStack's `lanes = columns` with the same item sizes, gaps, and `getItemKey`. The geometry engine computes the authoritative item rectangles and the shortest-column/leftmost lane assignment. A parity test asserts that every virtual item lane equals the geometry lane on the 20K fixture. If the library's assignment ever diverges, the parity test fails; the geometry result remains the source for rendered positions.

**AR-8:** Phase A builds the four RD-02 stories and the named 20K benchmark, not the full photo-library recipe. `@dnd-kit/core` is deferred to RD-04 because nothing in Phase A uses it. The shared fixture uses deterministic aspect ratios and data-URL thumbnails so tests do not depend on the network.

**AR-9:** `pnpm test:browser` is the fast Chromium check. `pnpm test:browser:all` runs Chromium, Firefox, and WebKit. CI has a separate `browser-matrix` job for all three and a separate `performance` job for `pnpm test:perf`. The existing `verify` job remains the unit/type/build gate; the phase Verify line combines `pnpm verify && pnpm test:browser && pnpm test:perf`.

**AR-10:** `vitest.config.ts` remains the jsdom unit config. `vitest.browser.config.ts` includes `test/browser/**/*.browser.test.tsx`; `vitest.perf.config.ts` includes `test/perf/**/*.perf.test.tsx`. Both use `@vitest/browser-playwright` with `playwright()`. The browser/perf configs use the real browser APIs; the jsdom setup installs stubs only when the API is missing.

**AR-11:** The source layout is `src/components/TileGrid/` with the house-pattern files plus `geometry/`, `virtualization/`, `selection/`, `marquee/`, `devWarnings.ts`, and `stories/`. Public types live in `TileGrid.types.ts`; internal geometry types live in `geometry/types.ts`.

**AR-12–AR-24:** The user confirmed the proposed technical defaults as a batch on 2026-10-20. They are derived from the confirmed scope and the RDs: band virtualization for fixed/justified/mosaic and item/lane virtualization for masonry; the Phase A public subset; the shared 20K fixture and story names; the test file map; the performance methodology; the CI browser-matrix/performance jobs; the pinned dependency versions; the mosaic aspect-ratio clarification; the `devWarn`/stub strategy; the no-SSR/E2E decision; the generic `forwardRef` pattern; the handle semantics; and the Phase A documentation/packaging scope.
